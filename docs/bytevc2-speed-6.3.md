# 6.3：ByteVC2无缓存首次转换测速

2026-11-08，本地开发候选。用户要求真实红果、只有ByteVC2且无已转换缓存时提速，同时保留画质和可播放；用户明确接受输出增大，优先画质和速度。不发布、不签名/公证、不替换正式应用。

## 最终实现

`src/native/bytevc2.js`在macOS arm64同进程完成ByteVC2软件解码与系统VideoToolbox H.264编码。参数为`h264_videotoolbox -allow_sw 0 -realtime 0 -q:v 68 -profile:v high -pix_fmt yuv420p`。没有缩小画面、降帧、裁时长或强填颜色；音频`copy`，MP4 faststart。qscale不是CRF，不能通过数值大小直接比较画质。

保留单转换队列、前台优先与CPU解码2线程。硬件编码器明确不可用/失败，或输出触及既有大小上限时，在同一次队列占用内最多重试原`libx264 veryfast CRF23`。取消、输入、磁盘与内存故障不盲目重试；两种编码均失败或超限则清理部分输出并释放队列。现有线上大小上限未提高。其他平台继续原软件路径。

`scripts/build-librempeg-source.sh`只在arm64启用VideoToolbox，保持原固定Librempeg/x264提交；精简组件不包含联网协议或本轮画质分析滤镜。上游缺少内部函数声明，新增一行头文件声明补丁，没有禁用编译错误。构建可重复识别已应用补丁；对应源码包包含两个原始固定归档、脚本和补丁。Mac准备脚本用脚本/补丁/二进制SHA失效缓存，并检查硬件编码器实际存在。

## 实测方法

设备：Apple M5、macOS 27.2、arm64。随机选择有真实ByteVC2候选的红果分集后重新取源下载：《我都元婴期了，你跟我说开学第四季》第1集；seriesId `7702841940475120702`，vid `7702841946812714008`。

输入ByteVC2/CENC，1920×1080，模型时长136.998秒，17,152,775字节，SHA256 `1117631c77a784cbc90f1f2686702e26be9d621c1caf4dbab3b487902a7a5449`。恢复测试进程时再次下载核对输入哈希相同，密钥仅在进程内存，不保存签名媒体地址或凭据。

所有计时都从转换调用前到输出完整性检查结束，每轮使用新输出文件，无已转换缓存、不含网络下载用时。没有清除操作系统文件缓存，因此“无缓存”指无转换结果，不能冒称磁盘/CPU缓存均冷。顺序执行完整转换，不与其他转换或质量分析并发。基线用原软件共享转换函数及原精简组件；最终候选用修改后的真实共享函数和重建精简组件，确认返回编码器为VideoToolbox。

| 项目 | 原软件 | 最终接入硬件编码 |
| --- | ---: | ---: |
| 第1轮 | 32.58秒 | 15.85秒 |
| 第2轮 | 35.08秒 | 15.59秒 |
| 平均 | 33.83秒 | 15.72秒 |
| 输出大小（十进制MB） | 60.91 | 93.11 |
| 对原片PSNR | 45.689400 dB | 47.894181 dB |
| 对原片SSIM | 0.990946 | 0.992380 |

平均快2.15倍、等待减少53.54%；体积增加52.86%，用户明确接受。原型q68另两轮15.48/15.91秒，与最终接入结果一致；不将原型二进制冒充最终组件。q65候选SSIM略低于基线被排除；q66/q75虽可播放，最终按用户偏好选择画质余量较大的q68，没有继续加入参数选项。

PSNR/SSIM使用同一固定Librempeg直接解码原始ByteVC2作为参考，对比全部4109帧，不经原软件输出充当“原片”；不生成巨型原始YUV中间文件。最终接入第1轮与两轮q68原型的指标一致。转码仍属有损编码，指标提高表示本样本相对旧方案更接近原片，不等于逐像素无损或对所有片源的保证。

## 完整性、画面与播放

- 对最终接入输出完整解码：4109视频帧，30fps，1920×1080、yuv420p、H.264 High、SAR1:1；视频136.966667秒、容器136.997007秒。与原片的帧数/时长一致。
- TV范围与bt709空间/传递/基色信息保留，与基线和原片一致；没有以强填元数据掩盖颜色差异。
- HE-AACv2、44100Hz、双声道、时长136.997007秒；提取压缩音频包SHA256与原片一致。
- 开头10秒、中段70秒、结尾126秒抽帧并排核对，未见明显失真；图片位于本轮隔离目录，不当作完整逐帧人工审片。
- Ego Lite打开最终`integrated-1.mp4`：先确认muted=true/volume=0，再播放至1秒、跳70秒后继续、跳134秒播至136.997007秒结束。无媒体错误，抽样播放掉帧0；不是完整137秒连续实时播放，也不是所有第三方播放器验收。
- `node --test src/native/bytevc2.test.cjs`：24/24通过，涵盖硬件参数、软件回退、双失败/双超限清理、队列释放、优先级、取消、存储/输入故障、凭据脱敏与完整性保护。
- 更新后的真实精简构建成功，架构和仅系统动态库依赖校验通过；只读代码审查未发现确定性P1/P2。构建中曾发现macOS patch逆向dry-run会误判已应用，现用声明存在检查及正向补丁修复，成功产物来自修正脚本。
