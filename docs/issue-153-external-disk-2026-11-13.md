状态：基于 7.1 源码的本地修复，未升版、未打包、未安装、未发布，未回复或关闭 Issue。

## 原因与安全边界

macOS 的 exFAT 卷上，独占创建的空文件可能先返回负数临时 inode，分配数据簇后变为正数；截断为零后再次写入还会换号。原流程在空文件阶段保存身份，之后严格校验判定文件已被替换，下载失败并保留残留。APFS 对照正常，7.0 和 7.1 冻结源码均复现此机制。反馈者的操作系统与磁盘格式尚不明确，不断言其设备已验。

修复集中于 `src/native/download-temporary.js` 和 `src/native/bytevc2.js`：

- 初始编号为负数时保留 `wx` 创建得到的原始句柄，经该句柄给空文件写入一个预留字节，获得有效编号。正常下载或转换会覆盖该预留字节。
- 写入或截断后，只在原始句柄的 `fstat` 与当前路径 `lstat` 的正数 inode、设备号及纳秒创建时间严格一致时，更新持久化回执。负数和零值不直接授权发布或删除。
- 原始句柄跨 ByteVC2 硬件失败后的软件回退保留；最终回执同步给下载任务。取消、失败和清理均关闭句柄。
- 清理先核对目录身份；被替换文件、未知文件、旧负数回执和不安全的旧 Number 身份继续保留。正数身份的普通磁盘沿用原有校验。
- 保留现有 `COPYFILE_EXCL` 防覆盖发布流程，没有改下载协议、来源限制或删除授权。

旧失败任务手动重试会新建独立临时目录；此次不强行认领或删除旧的不明残留。
