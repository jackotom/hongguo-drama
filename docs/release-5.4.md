# 红果短剧 5.4 源码升级目标

状态：开发中，未发布安装包。最初复现的取源空响应后续出现恢复，已完成真实下载与解码；不能将外部恢复归因于本地代码，也不等于桌面播放验收通过。当前正式下载仍为 5.3。

## 变更

- 扫码确认与取消/退出使用会话校验，过期异步请求不能保存登录态。增加独立沙箱官网登录窗口，凭据只保留在主进程并验证后加密保存；窗口关闭撤销待完成的验证。
- 移除剧库记录时清理本剧在线与兼容缓存，取消并等待本剧转码；保留下载视频、其他剧缓存和正在使用的文件。清理失败保留剧库记录以便重试。
- 观看记录按明确季号分组，支持展开折叠、人工确认同剧、移出分组、恢复自动分组及已看完标记。分组决定仅存本机，只改变展示，不改变更新通知和检测范围。
- 新增同局域网 DLNA 搜索、单集投屏和播放/暂停/停止。仅向选中的设备提供随机媒体能力地址，支持 Range，停止撤销服务；不传递平台凭据或原始媒体地址。在线投屏先完整缓存本集。
- 取源失败时隐藏不适用的“转码后播放”。修复初始设备注册消耗播放请求预算的问题；空响应时即使设备刷新处于冷却期，也允许一次备用官方主机请求，使用新连接。单次取源最多两次模型请求，保持设备刷新频率限制。

## 2026-11-02 播放故障实网定位

从官网当前真人剧目录的 24 条记录中随机选择《她的备用联系人》（series_id `7700130502790892568`），目录及 70 集分集信息可读取。第 1、2 集取源失败。第 1 集 `7700132359982550040` 的来源分类为网页 PREVIEW_ONLY、App EMPTY_RESPONSE、旧接口 EMPTY_RESPONSE，与 Issue #84 的故障阶段一致。

在同一注册身份上对照普通请求与携带平台注册的白名单 Cookie，请求均为 HTTP 200、空正文。官方 b/hl/lf 三个主机的有限对照也均返回空正文。没有将预览视频作为完整片源，没有导入他人的设备身份或登录凭据。

用户确认官方 App 正常，因此不能按平台整体停服处理；仍需在用户电脑网络对照。

初次同身份无签名与目录签名试验对照也均为空；当时未将试验方案写入生产代码。后续根据 #86 新证据恢复播放专用签名，见下文。

代码修正后的首集 1080p 实网取源仍返回 EMPTY_RESPONSE（约 5.36 秒）。这些结果只能确认本环境中的上游空响应，不能证明是某个签名字段、用户电脑、IP 或作品权限导致。这是初次失败时的记录；后续恢复与真实媒体验证见下文。

## #86 新证据后的播放签名修复

参考 [#86 用户对照与建议](https://github.com/jackotom/hongguo-drama/issues/86#issuecomment-6573115123)，5.4 的 `playbackRequest()` 恢复播放专用签名：对最终主机、query、实际 POST 正文字节和时间戳计算 x-gorgon / x-medusa / x-helios 等请求头；保留原播放 UA。主机切换、设备更新和重试都重新签名，注册流程继续使用原二进制协议，不混入账号 Cookie。

回归检查验证 query ts 与 x-khronos 一致、query _rticket 与请求票据一致、正文不变、签名哈希分支可用、x-gorgon 与实际 query/body 绑定（正文改变签名即不匹配）、多个并发播放保持注册身份、备用主机重新签名。13 项 App 片源检查、空响应恢复检查、17 项来源恢复检查及 221 项单元测试均通过。

补签后的实网验证：从当前真人剧目录随机选取《人前小保姆，人后是亲妈》（series_id `7699859403758914622`）。两集 App 1080p 片源成功下载，分别 11,059,418 与 9,050,409 字节；解密/封装通过，均为 HEVC 1080×1920 / AAC，各前 10 秒音视频解码通过。临时测试资料独立，无声音输出，未进行 GUI 或人工听音验收。

同身份的 5.3 无签名 / 5.4 签名直接对照在另一时点均出现 200+空正文，因此不能将用户提出的“未签名一律失败”视为本环境已独立证明的事实，也不承诺签名消除全部间歇错误。签名缺失已修复并通过成功路径实测；长期稳定性、实体设备与三端安装包仍待验，未发布 5.4。

## 5.4 代码复审

- 修复官网登录窗口关闭期间 Cookie 读取的竞争；同一窗口的 Cookie 事件串行合并，关闭后不能重新发起登录验证；启动旧 Cookie 清理完成后才执行账号操作。
- 投屏连接、停止及退出增加取消信号和会话归属校验，避免停止后迟到的 Play。失败的新请求不解除已有文件的保护；文件引用按路径计数。界面可取消准备/连接，切集撤销尚未完成的旧集请求。
- 支持 DLNA URLBase 与带命名空间的设备描述。按剧清理等待本剧准备任务退出；分组忽略失效目标并防止跨来源合并。
- 复审后 228 项单元测试全部通过，13 项 App 片源、17 项来源恢复、App 空响应恢复、观看记录显示、按剧清理及投屏文件引用检查通过；前端生产构建通过。窗口安全为静态/隔离检查，不等于真实 Electron 桌面启动。
- 本轮仅生命周期和展示逻辑有改动，未重复下载真实视频；播放签名与上轮真实两集下载/解码记录保持不变。实体电视、GUI 播放和安装包仍未验收。
