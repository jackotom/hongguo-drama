# 老电脑兼容播放

2026-10-30：已完成本机真实红果视频验收与 Mac arm64 独立试用包。尚未正式发布，不替换正式应用。

同日已整合到4.9本地版本，与Dock图标修复一起验收，见 [4.9说明](release-4.9.md)。下方4.8.0试用包与耗时为整合前的历史验收证据。

## 场景与使用

针对显卡不支持 H.265、每集先黑屏再提示转码的电脑，在播放页“在线播放清晰度”或播放器“清晰度”菜单选择“老电脑（H.264优先）”。选择保存在本机，后续切集、预取和重新打开沿用。

- 红果在线播放复用原有兼容片源选择，优先 H.264，可能低于 1080P。
- 片源明确标注 H.265 且“兼容模式”开启时，先走已有 H.264 转码，再交给播放器；不等黑屏或解码报错。转码仍有等待及 CPU 开销。
- H.264 直接播放。未标注编码的片源、已有本地视频沿用原来的解码失败兜底。
- 关闭“兼容模式”后不会主动转码。其他来源仍由其片源决定；默认自动1080P优先和手动720P/1080P的行为保留。
- 转码失败最多重新取源一次，再走原有下载回退；老电脑模式的下载回退使用兼容优先。快速切集会取消旧转码，过期结果不能覆盖新集。
- 不修改下载原件。CPU 很慢且上游只有 H.265 时，仍不能保证即时播放。

## 验证

两项定向检查，全部为隔离的离线模拟，不接触正式账号和视频目录：

1. `node scripts/check-player-online-quality.cjs`：选择保存、暂停/位置保留、切集、预取、提前转码、直接播放H.264、取消和过期结果、失败有界与下载回退，以及原有自动清晰度回归。
2. `node scripts/check-player-online-quality.cjs main`：真实主进程 IPC，确认直连、预取、命中缓存均返回编码信息且不返回上游媒体地址，并回归清晰度隔离。

## 真实红果素材与打包验收

- 从实时红果 App 真人剧目录随机选择《卖掉养老房那天，我重获新生》，series_id `7696351358173072409`，真实下载第1、2集。两集均为1080×1920 HEVC/AAC，分别为12,203,631字节、8,594,128字节；原件保留。
- 测试采用独立 profile 和下载目录。主进程对所有窗口强制静音；播放前再次设置 muted、volume=0 并断言，全程无声。未使用彩条或生成视频。
- 验收入口仅把本轮已有下载暂时按在线播放处理，强制走生产代码原有的软件重建路径。没有伪造编码信息、媒体错误或上游视频；两集均用真实 HEVC 输入，经 libx264 软件转码后得到 H.264/AAC。
- 两次软件转码分别耗时14.6秒、10.8秒。两集各实际播放约3.96秒、均新增120帧；画面人工复核，暂停、拖动到3.25秒、切集及“老电脑”选择保留通过。此耗时仅代表本机，不代表旧电脑速度。
- 正常试用包采用 main.js 原始入口，无 test-harness 或验收钩子。包内main/preload/前端文件SHA256与当前工作区逐项匹配，FFmpeg/ffprobe可运行，本地ad-hoc签名校验通过。版本仍为4.8.0，未升版、未替换正式安装、未发布GitHub。
- 正常入口试用包由原生界面操作再次验证：选择“老电脑”，在线播放同剧第3集，显示真实转码进度后正常播放至约46.9秒，已静音暂停；当前窗口保留供试用。
- 前端构建通过。前轮31项定向离线回归仍有效，本轮未重复未变的源码检查。

证据：`.planning/legacy-playback-20261030/real-acceptance.json`、`trial-verification.json`、两张真实播放截图及构建日志。试用应用：`trial-build/mac-arm64/红果老电脑试用.app`；ZIP：`红果老电脑试用-4.8-mac-arm64.zip`。测试数据和素材仅保存在本机，不放入分发ZIP。

## 限制

上游本轮随机片源均提供HEVC，不能保证有H.264可直接播放；本次真实验收覆盖的是“提前转码”路径。没有验证画中画、自动连播/删除、Windows/Intel实体机或低配CPU速度。Mac试用包只有本地临时签名，未公证。不能据本机结果宣称旧Windows电脑已实测兼容或能秒开。
