# Issue 178／179 处理记录（2026-11-23）

## Issue 179：播放接口空响应

- 现场复现：同一分集在主播放 POST、备用域名、官方单集 `video_model`、`video_tab` GET 与旧接口均返回 HTTP 200、0 字节正文；换新匿名身份也不恢复。
- 这不是本机网络、播放器解码或 Token/登录失效。官网 SEO 页的 `360p.mp4` 只有 10 秒，继续拒绝作为正式播放或下载源。
- 官网网页播放器仍可调用 `POST /api/video/protected/fallback-play-info` 取得完整公开片源。真实分集实测为 H.264/AAC、360 × 640；两集完整时长分别为 92.67 秒和 99.28 秒，不是预览。
- 客户端将播放路径改为单轮有界探测：同一匿名身份复用，不再为每次加速尝试连续注册新设备；每个入口空响应后等待 250ms 复探一次，再进入下一官方入口。
- 新增官方单集 `POST /novel/player/video_model/v1/` 的两主机回退。业务码 `110001` 仅触发一次新身份重试；普通空响应累计两轮且距上次换号至少 30 秒后才换号，避免把临时风控放大成注册风暴。
- 自动在线播放和固定 1080P 下载允许降级时，会使用上述完整公开片源；固定播放画质仍不静默降级，下载会明确提示实际质量。
- 匿名身份复用仍保留取消语义：设备注册 socket 由共享请求持有，最后一组消费者取消时才关闭，避免切集、关闭播放或重试留下悬挂连接。

## Issue 178：弹幕表情图片

- 官方弹幕正文把表情作为 `[爱慕]`、`[笑哭]`、`[没看够]` 等文字代码下发，没有单独图片地址。
- 显示层将已识别的常见代码展开为系统彩色表情图片，按原顺序和重复次数显示；未知代码保持原文，不丢内容。覆盖了当前实测三集出现的 `[偷笑]`、`[吃瓜]`、`[大笑]`、`[奸笑]`、`[微笑]`、`[捂脸]`、`[没看够]`、`[爱慕]`、`[爽]`、`[笑]`、`[笑哭]`、`[赞]`、`[送心]`、`[送花]`、`[饱了]`、`[鼓掌]`。
- 屏蔽、去重、聚合、弹幕宽度和长文本截断仍基于原正文；替换只发生在显示阶段。

## 后续集数与 8.0 回归补充

- GitHub #180／#181 反馈 8.0 只能播放或下载前几集，偶发播放也仅为 360P。复核同一部 73 集样本时，官网 `accessible_episode_cnt` 为 5：第 1、5 集可取得完整 360P，第 6、10、12 集由 `fallback-play-info` 返回 HTTP 403 `public_fallback_unavailable`，受保护的 `play-info` 返回 403 `protected_playback_unavailable`。
- App 侧第 1、6、10 集在当前上游状态下均返回 HTTP 200、0 字节。使用网页登录 Cookie 请求同两条网页接口，以及使用原生 `video_tab` GET、备用域名和 Electron 网络栈，结果仍为空，不能把网页登录态当作 App 片源授权。
- 8.0 的网页优先顺序会让可用 App 模型被普通公开 360P 抢先，因此已把取源顺序改为“`video_tab` → V5 播放接口 → 单集模型 → 旧接口”，整体再按“App → 官网公开源 → 旧接口”降级。App 正常时保留清晰度；App 为空且不在官网公开范围时，不再把公开页短暂预览冒充完整片源。
- 同一集第一轮官方入口全部空响应时，最多丢弃当前匿名身份并换号重试一次；两次换号间隔仍受 30 秒下限约束，避免把临时拦截放大成注册风暴。
- 官网明确的公开范围外响应标记为 `PUBLIC_ACCESS_LIMITED`。播放取源立即结束，不继续扫播放页；下载任务明确显示本剧公开源上限并停止自动重试，避免 #180 所报的长时间等待。
- 参考 1.0.137 的 SDK v5 路径，在旧接口全部空响应后调用独立 macOS arm64 取源执行文件：注册匿名设备、下载并校验官方 SDK 素材、运行 SDK 指纹核、换取 SDI token，再请求播放模型。执行文件成功后仍经过现有地址、编码、密钥和媒体校验。
- 2026-11-23 晚间实测《一把杀猪刀，供出女状元》第 1、10、12 集均取得 1080P HEVC 播放模型及解密密钥；arm64 最终目录包中，第 1 集静音连续播放至 0:34，切到第 23 集后静音连续播放至 0:29，画面和进度正常推进。
- 当前只有 macOS arm64 已构建并实播验收。macOS x64、Windows x64 和 Linux x64 尚未构建同架构 SDK 执行文件，不能声称这些平台已修复；本轮未打包正式发行版、未签名公证发布、未安装覆盖正式应用。

## 下载取源速度修正

- 批量下载后续集时，每集原先仍先串行扫描多组空官方入口，再等待在线播放 FIFO 的 1 秒间隔后启动 SDK。四个 1080P 分集实测总取源约 23.36 秒，任务完成时间依次拉到约 5、14、19、27 秒。
- 下载任务已知超出 `web_accessible_episodes` 时改为 SDK 优先；四条独立 SDK 请求可以并行，不再占用在线播放的串行节流。在线播放、预取和普通官方取源仍保留原 FIFO、身份轮换和 403/429 停止保护。
- 同一批四个真实分集改用新路径后，全部取得 1080P HEVC；未限制 SDK 并发时总取源约 3.34 秒，加入三进程上限后复测约 2.70 秒。媒体传输抽测首字节 297ms、8MB 用时 1.54 秒，约 43.5Mbps，确认原慢点不在 CDN 下载。
- 实际界面批量下载《小镇是非多之同床异梦》时，公开范围内的第 3～5 集仍走旧接口，任务分别约 7、20、28 秒；第 54～58 集走 SDK 新路径仅约 1～5 秒。因此数字分集全部改为 SDK 优先，复测第 3～5 集总取源约 2.02 秒。
- 定向验证：`scripts/check-desktop-source.test.cjs` 9 项通过；`app-source-current-recovery`、`app-source-video-tab` 与上述桌面取源共 37 项通过；取源重试策略检查通过。

## 并行 SDK 稳定性补充

- 数字分集下载统一改为 SDK 优先，不再区分官网公开上限；SDK 失败或平台不可用时仍回退原官方入口和网页公开片源。
- SDK 子进程最多同时运行 3 个；超出的下载只等待空闲槽位，取消后立即释放等待项。在线播放原有 FIFO、1 秒间隔和拒绝保护不变。
- SDK 首次初始化使用缓存目录独占文件锁，先完成匿名设备和固定 SDK 素材校验，再并行运行播放会话，避免多个首次下载同时抢写 `device.json` 或重复下载素材。
- 使用没有设备文件的隔离缓存（复用两份已校验 SDK 素材）并发实测四个分集：4.62 秒全部成功，只生成一份 1128 字节、权限 `0600` 的设备文件。
- 2026-11-23 重新构建时，固定源码地址当前返回的归档 SHA256 为 `7e6660313554ba388347397c1f551b93b419d27473c1f0718a5b76463b84d3b5`，与脚本固定的 `beebd9847e3214ca280cfe71320fb89eb2d5b4db18659803a3404ddac75dd5db` 不一致。构建脚本现在校验失败会删除坏下载并退出；本轮执行文件仅使用此前已通过校验的本地提取源码重编，干净机器上的可复现构建仍被该上游归档变化阻塞。
