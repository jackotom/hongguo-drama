## 已证实

### 1. 播放失败可以转成下载失败提示

- `src/components/Player.jsx` 的 `prepareNextEpisode` 在当前播放期间准备后续最多两集；自动画质顺序为 `1080p → 720p → auto`。`auto` 在这里表示兼容片源请求；固定画质不自动降档。
- `startOnlinePlay` 接管预缓存或重新准备时，所有允许的画质失败后调用 `recoverOnlineFailure`。
- `recoverOnlineFailure` 先查本机文件和已有下载，再调用 `downloadSingleEpisode`。其进入下载等待前会清空 `playbackError`。自动播放原本为 `auto` 时，下载兜底可能重新请求严格 `1080p`；此为既有业务逻辑，本轮不更改。
- 下载任务失败后，播放器每两秒刷新状态，主要展示 `ep.error`。用户看到的最后错误可能来自自动兜底下载，而不是最先失败的预缓存或在线播放。
- 预缓存失败本身不会立即中断正在播放的当前集；只有后续交接失败、或当前媒体自己发生错误时才进入后面的恢复路径。不能仅凭后台预缓存报错就判定前台播放失败。

### 2. 错误页换画质的指引与安卓设置入口不一致

排查时 `Player.jsx` 解码错误浮层提示“在播放设置中更换画质”，按钮导航到全局 `settings`。`android/mobile/settings.jsx` 只有“默认下载画质”；当前在线播放画质保存在独立的 `hongguo:online-quality` 偏好里。改变下载画质不能等同于改变本集在线播放画质。

最小前端改善：错误浮层直接展示已有在线画质选择，调用原有 `changeOnlineQuality`，或引导到本页已存在的在线画质入口；保留原取源与固定画质规则。可保留初次失败原因并标明“正在尝试下载后播放”，避免最后一条下载错误掩盖过程。不应为改善文案而偷偷禁止、增加或更改自动下载业务。

### 3. 取消边界确有临时文件遗留，但不是已确认的本次根因

`android/mobile/media.js` 在原生未加密媒体响应返回后，先检查 `signal.aborted` 并抛 `ERR_CANCELED`，此分支没有释放响应中的 `response.token`。后面的释放逻辑还没有执行机会。

已用一次离线定向命令复现：esbuild 内存打包实际 `media.js` 与 `transport.js`；仅替换取源与原生网络返回；令原生成功返回未加密 token 后、`await requestMedia` 继续之前触发取消。断言结果为 `ERR_CANCELED`，临时 token 集合仍有 1 个。命令退出 0；未联网、未写测试文件、未使用视频素材或把桩数据当作播放验收。

这证明一个清理边界问题，不证明频繁播放失败由此导致。既有 `mobile.test.cjs` 的取消晚到测试替换了整个 `prepareMedia`，因此覆盖桥层晚到释放，但没有覆盖这个函数内部的窗口。修复须改媒体桥，超出当前仅前端授权，保持原样。

## 源码候选与限制

1. **取消未传播到共享取源。** `media.js` 向 `fetchAppPlayUrl` 传入 `signal`，但 `src/native/app-source.js` 内部使用自己的 `AbortSignal.timeout(12000)`，未组合调用方信号；设备注册也有自己的时间预算。快速切集后旧请求可能继续占用原生工作池。原生池确为 `Executors.newFixedThreadPool(3)`，不是4线程。是否已拖慢本轮手机前台请求，尚无关联时序证据。
2. **备用地址只处理部分HTTP错误。** `media.js` 对 `HTTP_403/404/410` 有界尝试来源提供的备用地址；403先做一次 Referer 切换。TLS、连接错误、超时或跳转校验失败没有进入同画质备用候选。需要取得当次错误类别后再决定是否扩大可重试类别，不能对取消、安全拒绝和业务拒绝盲目重试。
3. **302与IOException还不能唯一定位。** 原生媒体跳转最多4次，每跳调用HTTPS域名白名单校验。非HTTPS、不允许的域名/端口、无效Location、过多跳转、读流错误都可能进入异常路径。现有 `HongguoNetwork` 仅记录异常类名，不足以由 `IOException` 区分上述原因。
4. **ByteVC2仍无安卓转换。** 安卓明确过滤 ByteVC2；自动在线模式已有画质和兼容源回退。如果所有可用档均只有 ByteVC2，现有安卓不能完成播放。不能以改错误文案声称支持；不能将桌面转换验收外推到手机。
5. **64MB是硬边界。** 原生下载/写媒体和本机读取均限制单集64MiB。超限会失败；现有原生错误通常以 `ERR_NETWORK` 传回，虽然消息会保留“文件超过本机处理上限”。该错误不应简单归为网速问题。未测试本轮是否触及此边界。
6. **内存压力仅为候选。** 整集读取、base64跨桥、解密与Blob会产生临时副本，同时有当前集和后续两集预缓存。未取得OOM、renderer退出或内存证据，不把播放失败直接归因于内存。
7. **签名与URL有效期。** 使用共享签名与取源模块，每次准备会重新取源；本轮没有签名错误证据。媒体404/410已尝试备用地址。若所有同批地址失效，需区分重新取源可恢复和来源明确拒绝，不能盲改签名或缓存。

## 最短检查顺序

1. **先对齐失败时刻与分集。** 记录剧名、集号、选中在线画质、是否本机文件、自动下一集/手动切集，以及失败前后截图。将前台当前集与后两集预缓存区分。
2. **网络。** 按取源、媒体响应头、媒体读体、准备四阶段记录耗时；仅记录HTTP状态、异常类别、主机名。出现302时记录 Location 的协议和主机名、跳数、是否命中允许列表，绝不记录完整地址。若本机与手机不同，只能说明路径差异，不能替代手机复现。
3. **格式与完整性。** 记录编码、实际尺寸、时长、字节数、是否完成解密与64MB边界；需要对照时只用随机真实红果整集，在独立测试目录核对哈希与完整解码。不得用彩条或伪造片源验收。
4. **解码。** 分开记录WebView媒体错误码2/3/4、readyState/networkState、播放时间是否推进与videoWidth/videoHeight；媒体错误码4本身不能唯一证明编码不支持。必要时同一完整文件对照，不能仅依赖来源声明的codec。
5. **配置和生命周期。** 读取当前在线画质、下载画质、预缓存开关、是否后台/锁屏、清理器退出原因；不要先清数据或改成低画质掩盖故障。取消后旧请求与Blob是否释放需独立核对。
6. **权限。** Manifest已有 `INTERNET`；媒体写入应用私有目录。除非现场有权限异常证据，不新增存储权限或放开TLS/HTTP。
