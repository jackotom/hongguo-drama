# 播放模型恢复范围（5.5 候选）

## HTTP 200 空响应

GitHub #91 的最新反馈包含连续切集和批量下载失败。社区报告部分设备身份只放行一次播放模型请求，原实现长期共享设备、空响应后每分钟最多更新一次，后续请求可能继续使用被拒绝的身份。

播放模型改为每次取源独立注册匿名身份；搜索与账号仍使用原来的共享身份。不带用户账号或登录令牌，不新增轮询。空响应仍最多尝试一次备用主机，按新身份和最终请求重新签名；HTTP 权限错误不新增重试。现有按集/画质请求合并及缓存继续生效。该调整可能增加匿名注册请求，不能保证消除上游限流、网络故障或全部空响应。

## 有效 JSON 缺少解密信息

采用 PR #92（roytjus）提供的受约束恢复路径。有效内联 `video_list` 缺少 `encrypt_info/spade_a` 时，只有视频身份、正时长和所选档位实际尺寸可确认，才读取模型已提供的 `fallback_api` 一次。

- 正常内联模型不增加备用请求。
- 备用视频身份必须与原模型相同，完整时长差不超过 0.5 秒。
- 备用档位必须有有效密钥或明确未加密标记；所有返回候选的实际尺寸均不得低于原档位。
- 沿用 H.264 优先、地址域名校验、解密与原 12 秒请求期限。
- 预览、错集、未知加密、无效密钥、非法地址及权限错误继续拒绝。

此路径修复缺元数据的有效 JSON，不处理 HTTP 200 空正文；两类错误分别处理。#87 的播放签名贡献归 jjay5520，#92 的备用解析及离线用例贡献归 roytjus。

## 本轮验证边界

按用户明确要求，本轮只做源码静态审查、必要发行构建和文件完整性核对，不运行新增或既有功能、单元、集成、桌面和硬件测试。保留并更新离线用例供后续使用，不能将贡献者在其他环境报告的通过结果当成本轮验收。未重新下载或播放测试视频。
