# 内联片源缺少加密信息时的一次备用取源

## 故障与范围

下游集成在 2026-11-03 遇到：播放接口返回 HTTP 200 和有效 JSON，精确分集
条目存在，内联 `video_list` 也有多档视频，但缺少 `encrypt_info` 和
`spade_a`。当前解析器因此返回 `INVALID_RESPONSE`，没有尝试同一模型
提供的 `fallback_api`。

这与 HTTP 200 空响应是不同情况。本修改不改变设备注册、请求签名、空响应
重试或全局重试次数，也不保证解决 #91 中的所有失败。

## 修改

- 抽取共用模型解析器，保留现有 H.264 优先、画质选择和媒体 URL 校验。
- 有效内联片源直接返回；仅缺少加密信息且能够确认原视频身份、正时长和
  所选档实际尺寸时，读取一次现有备用接口。
- 复用原请求的 12 秒期限和取消信号，不新增轮询或设备切换。
- 新备用路径要求 `video_id` 一致、备用模型自己的正时长与原模型相差不超过
  0.5 秒、有效密钥或明确未加密标记，以及不低于原档位的实际尺寸。
  此尺寸下限适用于所有返回的候选，包括 `allowLowerQuality` 模式。
- 预览、错集、未知加密状态、非法 URL、权限拒绝继续失败。明确加密但缺少
  密钥、或只有无效密钥的内联模型不会因此触发备用请求。
- 原有无内联列表的旧备用路径保持兼容。

## 验证来源与限制

下游问题样本为《重生想分手，太子爷不肯让我走第二季》，主剧编号
`7701643123985746969`，分集编号 `7701643128951802904`。原模型时长
56.007 秒；备用模型返回相同视频身份、相同时长、明确的未加密标记和
`key_seed` 编码的地址。下游修复后下载文件为 5,288,364 字节、HEVC
1280×720 / AAC，实测时长 56.006644 秒，整集音视频解码通过，临时媒体
已删除。这是此前下游集成的验证记录，不能当作本次桌面安装包验收。

本次上游移植以离线模拟 HTTP 响应回归：新增测试先在原代码复现失败，
再验证正常内联无额外请求、一次备用恢复、地址解码及备用地址、身份/
时长/尺寸/加密/域名拒绝、权限错误终止与共享请求期限。测试不联网，
不含真实密钥、登录凭据或带签名的媒体 URL。

