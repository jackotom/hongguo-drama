# Issue 71：下载提交失败后的重试

2026-10-29，本地修复并验收，仍为 4.6.0，未发布 4.7。保留 Issue 70 的注册恢复修复。

## 问题与修改

报告为“本集已尝试下载”，下载管理实际没有任务。报告未提供剧名、集数和运行环境，无法重放作者的相同片源。

- 在线失败后的自动下载仍在提交前记一次尝试，避免自动循环提交。
- 提示以真实任务状态为准：已有 pending/downloading 任务时等待；提交失败且没有任务时明确提示手动重试。
- 手动“重试本集”清除该集的尝试标记，允许再次提交；任务被移除后也能重新提交。
- App 取源区分 `NO_COMPATIBLE_SOURCE` 与 `QUALITY_UNAVAILABLE`。聚合错误只展示安全文案，不暴露上游响应。指定在线播放 1080p 仍不静默降级。

## 真实验收

从红果 App 实时真人剧目录随机选择《认下混混老爹，我一路青云》，series_id `7696744349203188760`。独立资料、独立下载目录，全程静音。

1. 专用验收包注入在线播放失败和首次下载提交失败；真实任务为空，首次只提交一次，提示没有虚构“已有下载任务”。
2. 通过原生 UI 点击“重试本集”，第二次提交实际走生产下载代码和红果上游。
3. 第 1 集下载 9,570,005 bytes，HEVC/AAC，1080×1920，时长 113.823991 秒。
4. 静音播放推进 6.923597 秒，解码 178 帧；实际视频帧与窗口截图已人工检查，画面正常。

本地证据位于 `.planning/issue-71/real-acceptance.json`、`actual-video-frame.png` 和 `real-playback.png`。验收注入仅存在于专用验收包，未放进交给用户的正常测试包。

## 正常测试包额外发现：拖动进度异常

正常包实测拖动第 1 集到片尾时出现主进程错误：

```text
TypeError [ERR_INVALID_STATE]: Invalid state: ReadableStream is already closed
```

本地协议把 Node 文件流直接传给 `Response`，取消旧读取时可能进入 Undici 异步迭代转换的重复关闭路径。独立取消读取实验以及现有流协议回归均复现相同错误。

完整文件和 Range 响应改用项目已有的 `Readable.toWeb` 转换方式。新增取消读取回归在旧实现上捕获 4 次 `ERR_INVALID_STATE`，修复后通过。没有增加全局吞异常处理。

最终正常包使用相同真实第 1 集，拖到 111.6 秒后正常结束并自动播放第 2 集，未再弹错。第 2 集由 UI 真实下载，6,287,116 bytes。开启自动删除后，仅独立测试目录的第 1 集副本与任务被移除；第 2 集及原验收下载均保留。第 2 集播放至 28.5 秒后暂停，自动删除已关闭。证据：`.planning/issue-71/normal-flow.json`。
