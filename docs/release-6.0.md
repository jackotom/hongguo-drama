# 6.0 兼容转换 CPU 占用修复

状态：已于 **2026-11-05 21:59（Asia/Shanghai）正式发布**，内部版本 `6.0.0`，标签 `v6.0` 并设为Latest。冻结源码 `c51b9e9378c27b5e84cd201a84b2df2a7a99579f`；后续文档提交不改变标签及已发布安装包。旧版5.9的构建、签名、公证与真实素材结果不作为本版证据。

## 修复

- #107：ByteVC2兼容转换原先可由下载及两个预缓存分集并行启动，解码与H.264软件编码未设线程上限。现共用一个可取消的转码队列，解码与编码各2线程，滤镜与lookahead各1线程。保留veryfast、CRF23、原尺寸及音频复制。
- 排队时当前播放优先于预缓存，预缓存优先于普通下载；同级FIFO。切到尚未完成的预缓存时提升原请求；后续画质尝试保持前台优先。已运行的转换不重启，避免丢失进度。
- 后续两集仍提前下载；只串行处理需要CPU转码的ByteVC2片源。普通H.264/HEVC播放、保帧、倍速、自动连播与缓存复用保持原实现。
- 排队任务取消后不创建输出；运行任务沿用终止和清理；失败释放队列，不阻塞后续集。
