## 本次确认的根因及修复

### 1. 清理未完成便删除唯一归属标记

起始工作区的 `cleanupDownloadTemporary()` 在尝试删除已验证文件后，无论目录是否还含未知文件、文件是否删除失败，都会先 `unlink('.hongguo-owner')` 再 `rmdir()`。`rmdir` 遇到 `ENOTEMPTY` 后被忽略；下一次检查又因为标记已消失拒绝目录，任务回执失去重试价值。

触发：未知文件、文件被替换、文件删除返回 `EBUSY/EACCES`、或目录删除本身失败。仅看“不误删未知文件”会漏掉“连自己的下次清理也被永久阻断”。

修复在 `src/native/download-temporary.js:80`：只在实时目录列表仅剩有效标记时删除标记；有残留则保留。空目录删除失败或标记移除后取消时，仅在目录当前身份仍与移除标记前一致时，以 `wx` 排他恢复标记。目录身份变化时拒绝恢复，不能为新目录补发凭证。

### 2. v2 为所有目录放弃严格身份

起始 `directoryIsOwned()` 只看设备号、目录类型、标记，正常文件系统上复制标记也能认领替换目录。文件级回执阻止了测试中的外来文件删除，但无法证明目录层检查有效。

修复在 `src/native/download-temporary.js:22`：v1 继续严格身份；v2 正常目录严格身份加随机标记；记录中为负的目录 ID 才使用标记兜底。实际删除每个文件前，再做一次目录与任务可删除状态检查。

### 3. 不必要的目录句柄打开成为跨平台清理门槛

起始 v2 每次验证都 `openSync(directory)`；平台拒绝打开目录时，所有文件身份即使正常也无法清理。用拒绝目录打开、仍允许真实文件打开的隔离故障注入复现。

移除这项不提供相对句柄删除保证的检查。目录类型、设备号、适用的严格身份以及标记文件的 `lstat`/`O_NOFOLLOW`/`fstat` 校验保留。该测试证明错误分支兼容，不是 Windows 设备验收。

## 未消除的边界及其他相关风险

1. **已有 v1 负身份和无回执孤儿目录不被追认。** 新规则不会自动“修好”旧未知目录；应由用户确认后手动处理。明确仅删除记录也会丢弃该记录的临时文件回执，这属于已说明的用户选择。
2. **负 ID 随机标记可被有磁盘写权限者复制。** 它用于关联任务回执，不是不可复制的文件系统身份或对同权限本地用户的隔离。该分支仍逐文件校验，不递归删除未知内容。不能承诺替换目录本身总被识别。
3. **删除标记和删除目录不是原子操作。** 进程恰在两者之间崩溃、恢复标记失败，或负目录身份在恢复前再次变化时，仍可能保留无法自动认领的目录。此时宁可保留，不给变化目录补发授权；本次未引入新的事务/孤儿回收格式。
4. **初始化也存在无回执窗口。** `mkdtemp`、写标记和首次 `onChange` 持久化不是原子事务；崩溃或写盘失败可留下孤儿目录。固定名字、时龄或常量标记无法安全补足任务归属。
5. **旧记录无法追溯之前的磁盘变化。** 后续补丁已关闭临时清理期间发生符号链接替换，以及正常安全 inode 可比时普通目录替换的已复现窗口。旧记录首次核查时缺少历史身份，仍不能凭本次快照证明此前未被替换；没有可用安全 inode 时仍回退到路径/设备号，不能区分所有普通目录替换。
6. **普通路径 API 的最终检查/使用竞争仍在。** 末级文件检查、目录校验与实际 `unlink/rmdir` 之间仍可发生替换。没有把持有 FD、`O_NOFOLLOW` 或测试通过描述成消除所有祖先路径竞争。
