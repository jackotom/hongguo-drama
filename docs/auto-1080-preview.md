# 1080P优先自动换档验收

2026-10-30，用户已完成本地4.7.0独立测试包的试用，修改纳入4.8发行目标；当前尚未发布4.8，最终状态见 `release-4.8.md`。以下是发行前验收记录。

## 使用方式

播放器选择“自动（1080P优先）”。在线播放先请求1080P，失败后尝试720P，最后尝试兼容片源；切换保留进度及暂停/播放状态。解码失败时先保留当前档的兼容转码与一次缓存重建，仍失败再换档。关闭兼容模式时直接换档。

每次播放有界尝试，不自动从最后一档循环回1080。手动重试或换集重新优先1080，切集/切画质后的旧响应不能覆盖新请求；后续预取也从1080开始。

手动选择720P/1080P仍不自动降级；其他来源沿用来源支持的画质。已有本地视频不强制重下。自动换档均失败时沿用本地文件/下载回退，下载默认“自动”时使用1080优先，手动下载画质设置保留。

## 验证

- 19项清晰度、20项下载回退、22项续播/兼容回归，共61项通过。新增自动换档与兼容保护用例先在旧实现失败，再修复通过。
- 前端和Mac arm64测试包构建通过。包内main/preload/前端产物与工作区SHA256一致，正常入口为main.js，不含test-harness或故障注入；FFmpeg/ffprobe可执行，本地临时签名核对通过。
- 最终随机选择真实红果App目录《归路》，series_id 7699683909419666457，第1、2集。真实下载并静音播放，实际1080×1920与720×1280均经解码和ffprobe确认；没有彩条或生成视频。
- 验收包先真实播放1080；注入媒体错误后实际切到720，保留1.960053秒暂停位置。三档全失败时只提交一次下载；真实点击“重试本集”，从1080重新尝试，注入1080取源失败后用真实720片源接续播放。
- 故障只在专用验收包中注入；交给用户的正常测试包无这些钩子。所有测试使用独立profile/下载目录、mute-audio，正常包当前静音暂停，自动删除关闭。

## 限制

画质档位取决于上游；请求720P不代表上游必然有720P档，现有后端也可能返回更高尺寸，因此验收按实际分辨率判断。仅Mac arm64真机验证；未覆盖Windows/Intel硬件、长期弱网和所有第三方来源。测试包未公证、未发布。
