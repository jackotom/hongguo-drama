# #157：下载成功后临时文件 EPERM 误报修复

日期：2026-11-16。初次修复时仅修改本地源码；后续已构建7.5候选，仍未正式安装或公开发行，不改变v7.4标签和正式安装包。最终平台状态见[7.5回执](release-7.5.md)。

## 原因与处理

7.4 的 `publishDownloadFile` 在成功发布最终文件后立即 `unlinkSync` 临时文件。解密和转换路径又在 `finally` 中调用 `removeOutput`。这两处删除错误都会进入下载失败分支，即使最终 MP4 已经保存。

本次取消发布函数中的立即删除；解密／转换失败时仍尝试清理并保留原始错误，成功后统一交给任务外层已有的身份校验清理流程。该流程遇到活跃句柄删除失败后关闭句柄，再按文件身份重试。持续被占用时记录不含路径的清理告警，保留任务凭据供后续安全清理，不改变下载完成状态。未放松媒体校验、发布冲突检查和文件身份保护。

7.5补充：最终文件改用 `COPYFILE_EXCL` 独占复制，避免延后删除硬链接改变最终文件 ctime、使完成文件身份失效。8项EPERM回归增加清理后完成身份仍有效的断言，先失败再修复通过。现下载集成64/64、文件安全脚本及逐集重试15/15通过。真实随机两部短剧各下载一集1080P，注入持续EPERM后均完成；释放占用后临时目录清零，最终文件身份仍有效。Windows最终包另验，不外推Mac结果。
