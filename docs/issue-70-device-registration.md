# Issue 70：匿名播放设备注册失败

日期：2026-10-29。状态：本地源码已修复并验收，已构建并打开独立测试应用；未升版、未发布。

发布安排：用户确认本次修复保留，等待后续其他问题或改动一起发布 4.7；当前不升版、不创建标签、不发布 GitHub Release。

## 原因与范围

`getPlaybackDevice()` 原先会永久缓存首次注册失败的 Promise。首次请求遇到短暂断网、超时或服务异常后，即便网络恢复，同一进程里的播放、下载、App 搜索与账号身份读取仍使用失败结果，只能退出应用重新启动。

注册错误还会被统一转成 `DEVICE_REGISTRATION_FAILED`，丢失安全的原因分类。下载调度器因此无法将其中的网络、超时和服务端暂时故障识别为已有重试机制支持的临时错误。

本机直接调用真实注册接口约 304 ms 成功，未自然复现反馈者的首次注册失败。以上修复解决应用侧失败不能恢复的问题，不代表已经确认反馈者的网络、代理或上游拒绝原因。

## 修改

- 首次注册失败只缓存 10 秒；冷却结束后的下一次调用可以重新注册，无需重启。
- 并发调用继续共享同一请求；重复失败重新计时，成功身份继续复用。原有身份续期每分钟最多一次的限制保留。
- 错误只保留白名单原因：网络、超时、HTTP 状态、空响应、无效设备编号、服务拒绝、安全校验。原始响应、凭据和设备身份不附加到异常。
- 取源提示展示上述安全原因；网络、超时及 HTTP 临时错误沿用现有下载重试规则，服务明确拒绝和无效响应不被当作网络故障。
