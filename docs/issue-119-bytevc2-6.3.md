# 6.3：减少 ByteVC2 下载中的额外等待（#119）

状态：本地源码修复，未发布、未公证、未替换正式安装。用户选择“保证可播放，尽量避开或加速转换”，不默认保存普通播放器无法播放的原始ByteVC2。

## 修复的实际问题

1. **片源选择会优先不必要的转换。** 固定720p时，较小尺寸ByteVC2可能排在同样满足要求的1080p H.264／HEVC前。现在在满足所选画质的组内，先选无需ByteVC2转换的编码；普通编码仍优先最小满足档，同尺寸优先H.264；不满足组仍保留从高到低的既有回退顺序。没有以低画质兼容源替换固定高画质的规则变更。
2. **已转换缓存跨画质键漏用。** 自动在线播放通常先请求1080p，完整结果存在vid:1080p；默认自动下载只查自动key，导致重新取源、下载和转换。现在精确key优先，再检查同来源／同剧／同分集的完整缓存，实测尺寸并作现有解码抽查后才发布文件。
3. **同集准备与下载重复工作。** 下载先尝试完成缓存；没有满足结果时等待已有红果同集准备任务，完成后复用。下载取消只结束自己的等待，不取消正在播放的任务；准备失败后允许下载独立恢复。等待结束／准备完成竞态后会再检查缓存，避免刚完成结果被漏过。

仍保留来源锁定与身份复核、固定画质实测、取消、独占发布、现有文件保护、单转换队列、当前播放优先、解码／编码各2线程和veryfast／CRF23参数。没有新增依赖或硬编码器选项。
